# 推荐友好信号与平台安全门

本文把“提高获得推荐的机会”拆成两类：微信公众平台规则中心公开且可以直接执行的安全门槛，以及作者可以通过文章和后台数据验证的优化假设。两者不能混写。

## 来源与证据边界

主要依据：微信公众平台规则中心（公众号规则，检索日期：2026-08-31）

- [微信公众平台规则中心](https://mp.weixin.qq.com/webpoc/ruleCenter?type=oa)

规则中心公开内容明确强调：平台鼓励用优质内容获得用户自发分享和关注；标题扭曲事实、无中生有或煽动夸大，会损害阅读体验并可能受到文章处理或账号功能限制；诱导分享、诱导关注、跨平台刷量和骚扰式触达会破坏生态；原创声明只适用于自行创作、未侵犯他人权益且符合平台规范的作品。

平台没有公开一套可验证的“推荐分数公式”或固定权重。因此，本文中的阅读完成、收藏、分享、评论等是**优化和诊断用代理指标**，不是微信官方确认的排序因子；不能在文章、报告或对用户承诺“满足某指标就一定被推荐”。

## 标题注意力与具体实体

标题吸引力不是单一的“热度”。候选标题可以从以下信号中选择一个主信号、最多一个辅助信号：

- **热词/当下事件**：近期发布、政策变化、行业争议或正在发生的事件。
- **代表性实体**：读者熟悉的产品、模型、公司、协议、框架或版本名。
- **技术名词**：能准确指向能力差异的术语，而不是泛泛的“AI”“智能化”。
- **具体结果或冲突**：前后变化、反常识结论、关键取舍或真实限制。
- **身份与场景**：明确哪类人正在什么任务中遇到问题。

这些信号是标题注意力的可测试假设，不是微信官方排序因子。标题应优先选择**读者最容易识别、正文最能证明、与账号定位最匹配**的那个词，而不是机械追逐热度。

### 具体化阶梯

写标题前先把主题从泛到具体排成一条阶梯：

```text
泛品类（AI 视频生成） → 代表性实体（Seedance） → 具体版本/能力（Seedance 2.5 的某项能力） → 真实场景与结果
```

在证据允许的前提下，优先使用更具体且更有辨识度的层级。例如，文章确实使用并验证了 `Seedance 2.5`，标题通常比“AI 视频生成”更容易让目标读者判断“这篇和我有关”；但这只是“具体实体 + 真实证据”的优势，不等于版本号本身能保证推荐。

### 使用与核实门槛

1. **亲历文章**：标题写具体产品/版本，正文必须有对应的真实操作、输入输出、截图、日志或测试条件；没有亲历就改成“官方发布了什么”或明确归属的外部案例。
2. **外部事实**：优先查官方公告、产品页、release note 或原始数据；记录官方名称、版本号、发布日期和当前可用范围。搜索摘要和二手文章只能做线索。
3. **主角一致**：标题实体必须是正文主角，并在首屏说明它是什么、改变了什么、读者能获得哪一个判断或动作；顺带提及的产品名不得塞进标题。
4. **时效边界**：能力、价格、灰度范围和入口可能变化；正文写明核实日期或版本，发布前重新检查，过期后不要继续使用“刚发布”“最新”等词。

`Seedance 2.5` 只是当前检索到的示例，不是固定关键词名单。模型应每次写作重新建立候选实体，不把旧版本名、竞品名或热词批量拼接到标题中。

## 一、发布前硬门槛

任一项不通过，都先修正文或降级输出，不用标题和互动把风险掩盖掉：

1. **标题与正文一致**：标题中的对象、结果、时间、身份和因果关系在正文中有证据；不使用夸大、无中生有、故意省略关键限定条件的表达。
2. **原创和授权可追溯**：只有作者自行创作且拥有相应权利时才建议声明原创；引用、改写、翻译、截图、图片和数据均标明来源或授权状态。不把“洗稿式改写”当原创。
3. **自然互动**：CTA 可以邀请读者回答具体问题，但不能用红包、抽奖、积分、礼品、现金、强制关注或强制转发换取互动，也不能要求用户完成与正文无关的跳转链路。
4. **不刷量、不互导**：不设计多账号互刷、跨平台异常导流、虚假评论、虚假点赞或购买流量来制造“受欢迎”假象。外部投放或社群分发必须在表现记录中单独标注。
5. **内容和落地页安全**：正文、封面、摘要、链接和后续落地页不含低俗、谣言、违法违规、欺诈或与标题不符的内容；不把用户正常阅读中断为关注或下载前置条件。
6. **商业关系透明**：推广、赞助、联盟或利益相关关系按实际情况披露；产品体验只写已发生的使用和验证，不冒充用户评价。

## 二、把推荐当作一条可诊断的漏斗

写作阶段只优化作者能控制的环节，发布后按同账号、同口径、相近主题比较：

```text
被展示 → 愿意点击 → 首屏继续读 → 读完/读到关键段 → 收藏或转发 → 真实评论/关注
   ↑                                                ↓
   └──────────── 负反馈、投诉、取关、跳出 ────────────┘
```

每个环节都要有文章内的可观察设计：

- **被展示后的点击理由**：标题、摘要、封面只承诺一个读者收益，关键词自然出现，不堆热词或制造假冲突。
- **首屏留存**：前 1-3 段交代具体场景、部分答案和证据，不用目录、宏大背景或“看到最后”拖延兑现。
- **继续阅读和完成**：主体控制在必要模块；每节带来新事实、证据、判断、边界或动作；长文用小标题、短段和图注降低跳出。
- **收藏/转发价值**：至少交付一个可以复用的清单、判断标准、步骤、模板、对比或反例。转发理由指向具体人群和具体价值。
- **真实互动**：只问一个容易回答且与正文有关的问题，不把“欢迎留言、求转发”当作内容价值。
- **负反馈防线**：删除标题党、空洞水段、重复搬运、过度广告、强迫关注和与承诺无关的外链；这些问题优先级高于增加字数或装饰。

## 三、搜索意图与账号长期匹配

公众号文章同时可能从订阅、社交转发和微信内搜索被发现。搜索友好不等于关键词堆砌，写作时执行以下可验证规则：

- 先写出读者会输入的一句自然问题，再让标题、摘要、首屏和小标题围绕同一对象和任务展开。
- 专有名词使用官方写法；别名、版本和缩写首次出现时说明，不用生僻词替代常用检索词。
- 一篇文章只服务一个主要搜索任务。若同时回答多个不相干问题，拆成系列或缩小标题承诺。
- 标题和摘要不写正文没有解释的热词；正文第一次出现关键词时立即给出人话解释或具体例子。
- 账号定位、栏目和读者问题要连续可识别。偶尔的热点可以借题发挥，但必须说明与账号主线的连接，不为追热度硬改人设。

## 四、发布后复盘规则

记录后台实际可见数据，缺失就填 `null`，绝不估算。建议在现有表现文件中增加：

- `clicks` 或后台等价的点击指标
- `read_through_rate`、`completion_rate`（只有后台提供时记录）
- `negative_feedback`（投诉、屏蔽、取关或后台等价指标）
- `distribution_context`：订阅、社群、投放、跨平台分发等
- `recommendation_observation`：是否观察到看一看、搜一搜或其他推荐入口的展示；没有证据写 `unknown`

诊断时不要只看阅读量：

- 展示有、点击弱：先改标题/摘要/封面与读者场景的一致性。
- 点击有、首屏跳出高：先改开头兑现、段落密度和第一张图，不先加 CTA。
- 读得久、收藏转发弱：补可复用的判断或步骤，并让转述对象更具体。
- 互动高但负反馈也高：检查诱导式文案、争议制造、广告比例和落地页链路。
- 推荐入口未知：不要把“没看到推荐”当成“没有推荐”，先补齐后台口径或标记未知。

单篇数据只能生成下一篇的假设。只有在同账号、同指标口径、相近主题和相近分发条件下出现多条同方向记录，才把某个标题角度、结构或选题写入稳定偏好。

## 五、对模型的禁止承诺

- 不声称“官方算法更喜欢某种固定字数、发布时间、emoji 数量或标题格式”。
- 不声称“提高完读率/点赞率就一定进入看一看”，除非用户提供了自己账号的可比数据，并明确这是经验假设。
- 不用“推荐”“爆款”“上热门”等结果词包装未验证的草稿；可说“推荐友好”“降低风险”“提高可测试性”。
