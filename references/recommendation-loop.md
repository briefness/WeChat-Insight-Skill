# 微信公众号推荐友好写作与复盘

生成完整文章、优化标题封面，或用户提供历史表现数据时读取本文。目标不是猜测推荐算法，而是提高选题匹配、点击后的阅读体验和真实读者反馈。

## 目录

1. 可控范围
2. 选题准入
3. 标题、摘要与封面协同
4. 首屏与正文节奏
5. 互动设计
6. 发布表现复盘

## 可控范围

不能承诺文章一定获得推荐，也不能把未经公开确认的信号写成平台算法事实。只优化作者能控制的部分：

- 选题与账号既有读者是否匹配
- 标题、摘要和封面是否给出准确的点击理由
- 首屏是否快速兑现承诺
- 正文是否持续提供新信息、证据或行动价值
- 结尾是否产生自然、低门槛的真实反馈
- 下一篇是否吸收同账号、同口径的历史表现

不要加入“固定字数”“固定发布时间”“多写热点词”等没有账号数据支撑的规则。

## 选题准入

写作前在内部完成推荐简报，不把它原样输出到文章：

1. **具体读者**：这篇最适合哪一类人，不使用“所有人”“泛用户”等空泛描述
2. **触发场景**：读者此刻遇到了什么问题或正在做什么决定
3. **单一收益**：读完后只保留一个最重要的认知、判断或动作
4. **独特证据**：相比同类文章，这篇新增了什么亲历、数据、案例、反例或判断
5. **账号匹配**：是否落在 `positioning.content_pillars`，是否命中 `reader_problems`
6. **转述理由**：读者会把它转给谁，具体因为哪一段价值

如果第 2、3、4 项答不清，先调整选题角度或缩小主题，不直接堆砌正文。账号匹配较弱但用户明确要求写时照常完成，并在使用假设中准确说明目标读者，不擅自伪装成账号主线。

## 标题、摘要与封面协同

### 先生成候选池

先在内部生成 6-9 个候选，不直接把第一批标题交给用户。至少为以下每种传播假设生成 2 个真正不同的角度：

- **明确收益**：读者能解决什么当下问题、获得什么判断或完成什么动作
- **认知冲突**：有证据支撑的结果与常见直觉哪里不同
- **身份共鸣**：哪一类具体读者正卡在什么处境或决策上

每个候选只保留一个主钩子。改动语序、替换近义词或增删标点不算新角度。配置要求输出更多标题时，从通过门槛的候选中补足，不为了凑数保留同义改写。

### 标题硬门槛

任一项不满足就淘汰，不进入最终备选：

1. **真实可证**：事实、数字、结果和身份有素材或可靠来源支撑
2. **正文兑现**：核心承诺能在首屏开始兑现，并由正文主体完整交付
3. **单一点击理由**：只突出一个问题、收益、冲突或处境，不堆多个卖点
4. **具体而不泛化**：对象、场景或决策足够明确，不用扩大到“所有人”“普通人”换取表面受众
5. **信息差可信**：说明文章要解决什么，同时保留值得点开的具体缺口；不故意藏答案，不制造虚假悬念
6. **账号和读者一致**：优先命中账号长期读者；用户明确要求账号主线外的主题时，准确匹配本篇实际读者，不伪装成账号主线
7. **手机可扫读**：核心信息前置，一眼能抓住主干；删除无贡献修饰，避免多层从句、连续标点和术语堆叠

直接淘汰只有情绪、没有信息的句式，例如“太强了”“终于来了”“不看就亏”；也淘汰没有结果或冲突的“我做了一个 X”“关于 X 的一些思考”“聊聊 X”。

### 内部评分与推荐选择

对通过硬门槛的候选按下列 7 项各记 0-2 分：0 分为缺失或冲突，1 分为可感知但不够明确，2 分为具体且有正文支撑。

| 维度 | 2 分标准 |
|------|----------|
| 读者或场景 | 目标读者能迅速判断“这和我有关” |
| 当下问题或决策 | 对应正在发生的问题、任务或选择 |
| 承诺清晰度 | 点开后能明确预期获得什么 |
| 证据或冲突强度 | 有具体结果、案例、反例或判断支撑 |
| 信息差 | 已给出方向，同时留下真实且具体的未知 |
| 账号匹配 | 命中内容栏目或长期读者问题 |
| 移动端可读性 | 关键词前置，主干短而完整，没有理解障碍 |

只保留总分至少 11 分的候选；不足时重新提炼角度，不降低门槛凑数。先选出每类传播假设的最高分候选，再输出其中 3 个标题（或按配置数量补充其他高分角度），把全局最高分标为“推荐”。同分时依次选择：正文更早兑现、证据更强、与同账号可比历史表现更一致的标题。历史表现只能作为弱证据，不能压过本篇事实和账号定位。

评分、淘汰过程和候选池只用于内部选择，不写进成稿。不能声称分数代表微信官方推荐概率。

标题负责准确承诺，摘要补充标题没有容纳的信息，优先补以下一项：适合谁、证据是什么、读完能带走什么。摘要不能只把标题换一种说法。

封面优先展示真实结果、核心物件或一个可识别的冲突，并从完整正文动态提取视觉概念。封面禁止使用橘猫、动物吉祥物或任何固定 IP；文字使用短关键词或短判断，不复制完整标题，不同时堆主标题、副标题和分类标签。标题、摘要、封面可以分工，但不能表达三个不同主题。

## 首屏与正文节奏

首屏依次完成三件事：让目标读者认出自己的场景、给出部分核心答案、展示继续读的证据或信息差。不得故意拖延答案。

正文围绕单一收益选择 2-3 个必要模块。每个模块至少提供以下一种价值：

- 新事实或新证据
- 新判断或成立边界
- 可执行动作或验证方法
- 推动故事或问题发生实质变化

实战、坑点、清单、对比和模板按主题选择，不要求篇篇齐全。删掉只负责报幕、重复、转场或制造情绪的段落。文章长度由证据和信息密度决定，不把长文当成完整度证明。

## 互动设计

CTA 只推动一个真实动作。需要评论时，问题必须具体且容易回答，例如让读者选择一个方案、说出一个遇到过的现象，或补充一个反例。不要使用“你怎么看”“欢迎留言”等空泛提问，也不要诱导分享。

默认核心目标包含互动，因此 `wechat.need_open_comment` 默认开启。用户明确关闭评论或文章不适合互动时，以用户设置为准。

## 发布表现复盘

生成前检查 `performance.history_file`。文件不存在或没有可比记录时静默跳过，不追问、不编造历史结论。

只比较：

- 同一账号
- 指标口径一致
- 发布时间和分发条件没有明显异常
- 主题、读者或文章类型相近
- 标题角度和主钩子已记录
- 额外社群分发、投放等分发条件没有明显差异

优先寻找可复用特征，不机械复用句式：什么读者问题更稳定、哪类标题钩子与正文最匹配、哪类证据更容易被读完、哪些模块经常造成阅读中断。只有后台实际提供展示量和阅读量时，才能比较同口径点击表现；只有阅读量时，不把阅读差异单独归因给标题。

单篇表现只能形成假设。至少出现多条同方向记录后，才能写入稳定偏好。没有展示量或样本过小的文章，不据此否定选题。

发布后可以提醒用户按后台实际可见指标补一条记录，但生成文章时不得把内部指标表写进正文或发布前检查。
